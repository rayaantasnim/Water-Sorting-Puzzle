Section 02

Eliminating Virtual DOM Overhead

Direct Memory Access Channels for 60FPS Fluid Transforms

In standard reactive component frameworks such as React, every minor interaction initiates a complex reconciliation phase involving virtual DOM tree generation, fiber traversal, and synthetic event propagation. When coordinating millisecond-accurate physics animations like test tube tilting and liquid pouring streams, virtual DOM diffing incurs unavoidable garbage collection pauses and dropped frames. Our architecture bypasses virtual DOM trees altogether. Gameplay tubes are managed via native HTML elements mapped directly to an in-memory 2D array matrix. Whenever a pour command executes, only the specific affected source and target container nodes are targeted via CSS transform updates, keeping memory utilization under 2 megabytes and CPU consumption near zero.

// Direct In-Memory Tube Array Representation

this.tubes = [ ['cyan', 'magenta', 'cyan', 'magenta'], ['magenta', 'cyan', ...], [], [] ];

// Direct DOM Node Selection & Mutation: Zero Reconciliation Delay

const sourceNode = document.getElementById(`tube-${sourceIdx}`);

gsap.to(sourceNode, { x: deltaX, y: deltaY, rotation: 82 });

Section 03

GSAP 75°-90° Pouring Mathematics

Trigonometric Vector Anchoring for Realistic Fluid Pouring

Achieving believable liquid pouring without full WebGL hydrodynamic simulation requires meticulous trigonometric keyframing. Using GreenSock Animation Network (GSAP 3), each pour action triggers a deterministic timeline. First, the source tube translates upwards and aligns horizontally with the target container lip. Next, dynamic rotation between 75 and 90 degrees is applied with a customized transform origin located precisely at the pouring rim. An embedded linear gradient beam element expands downwards to bridge the gap between cylinders. Simultaneously, the bottom-most fluid segment of the receiving vessel expands in height as the source segment contracts, creating an immaculate visual illusion of volume conservation that runs smoothly on low-power mobile devices.

Section 06

Pure Relative Path Architecture for GitHub Pages

Permanent Immunity Against Domain Subdirectory Asset Failures

A prevalent flaw in web application architecture is the reliance on absolute root slashes for asset resolution (such as `/css/styles.css` or `/js/game.js`). When deployed onto GitHub Pages or enterprise CDN subdirectories where the root path is shifted (e.g., `user.github.io/Water-Sorting-Puzzle/`), absolute references crash with 404 errors. Water Sort Puzzle adheres strictly to a 100% dot-relative path mandate. Every stylesheet reference, script source, image link, and inter-page hyperlink utilizes strict `./` prefixes. This guarantees that whether the directory is hosted on a local file system (`file://`), an internal test server, or deep nested cloud storage, all dependencies resolve with zero configuration changes.

❌ Absolute Path: <script src="/js/game.js"></script> // Breaks on GitHub Pages

✔ Relative Path: <script src="./js/game.js"></script> // 100% Resilient Everywhere
